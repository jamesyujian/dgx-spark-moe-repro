# N2 GB10 双机 MoE 配方 v0.2 — Release Notes

**一句话**：v0.2 不改数字，只把 N2 与 N6 边界白皮书 v1.0 对齐，并把两文之间的关系写成表。**没有任何新测量，因此没有新增待核项。**

- Tag：`v1.1.1`（基线 `v1.1.0` = `a494416`）
- 文件：`docs/N2_GB10双机MoE配方_v0.2.md`（595 行）、`docs/N2_dual_node_recipe_v0.2.en.md`（593 行）
- v0.1 的位置：仍在 `v1.1.0` tag 内；本版起出包

## 为什么做这个版本

白皮书 v1.0 发布后，两文出现同一批数字的两种写法（起服时长、四并发区间、SGLang 领先的相对值、`util` 的角色）。读者最容易被这类「同一事实两个口径」误导，所以改成**白皮书定值、N2 引用**的单源结构。

## 两块新增

**§0.1 数字口径** —— 七个定值映射到白皮书，并附三条引用纪律：

1. 不写「1→2 加速比」：该发行版单机装不下（155.4 GiB > 121 G），**同权重单机基线不存在**；也不得拿 14.71 去减别的模型算折扣率。
2. 四并发只给区间 **25.5–43.2**，且写明**两端点系反算**、与单次延迟不能对齐。
3. 时长必须给起点：**270 s（容器起算）** 与 **209 s（引擎初始化）** 不可混用。

**§0.2 交叉索引** —— N2 七节 ↔ 白皮书逐节，标「同源 / 本文专有 / 白皮书专有」。其中明确两条：**261 s 是 N2 专有首轮值**；**驱动 595.71.05 只在 N2 §1**（白皮书不列驱动号，只在 §9.3 否定「驱动落后」归因）。

## 其余六处修正

- §4：health 200 备注 → 「容器起服到就绪 **261 s**」
- §5.1：区间写全 **25.5–43.2** + 「端点反算」限定 + 等级「已核（二手，端点待核）」
- §7：SGLang decode 领先**拆分母**（对 marlin 15.3–16.0 %、对 b12x 20.5–21.2 %；长上下文 17.3 / 19.6 / 24.6 %），并写明「写全档 15.3–21.2 % 是错的」
- §9：新增 **EP**（框架开放、`deep_ep`/`mori` 缺件、单机无路径、未实测；禁写「EP 不可用」）
- §9：新增 **3 / 4 节点**（官方支持、未实测、CX-7 固件 ≥1.108.20）
- §9：新增 **116**（13.84 h 冻结机制未定、6 h 不构成已修复、§8 的 8 形状是单次 kernel 测量不得互推）
- §3：`util 0.82` 标为**实测工况值**（白皮书已把该条降为「建议」）

## English summary

v1.1.1 ships N2 recipe **v0.2**, an alignment-only revision: no new numbers, no new open items. New §0.1 pins seven values to the whitepaper's single source of truth and adds three citation rules (no 1→2 ratio, four-way as a range with back-calculated endpoints, durations always state their start point); new §0.2 cross-indexes N2's seven sections against the whitepaper and explicitly marks **261 s** and the **driver 595.71.05** as N2-only. Eight further fixes remove the remaining double-caliber spots (startup time, four-way range, SGLang denominators, `util` role), and §9 gains three boundaries: EP (missing `deep_ep`/`mori`, no single-machine path), 3/4-node rings (unmeasured, CX-7 firmware ≥1.108.20), and the 116 freeze (13.84 h, mechanism unknown, 6 h is not a fix). The v0.1 files remain in the `v1.1.0` tag and leave the kit from this release onward.
